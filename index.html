How I Use Claude Code CLI

What is Claude Code CLI?

A terminal-based AI assistant that can read your files, write code, run commands, and spawn sub-agents — all within your project directory.

The key differentiator: it can orchestrate multiple specialized agents in parallel, each with its own role, working on your codebase simultaneously.

Think of it as a CTO that can instantaneously spin up a full dev team on demand.

Prerequisites

✓ Claude Code CLI installed (npm i -g @anthropic-ai/claude-code)
✓ Anthropic API key or Claude Max subscription
✓ A clear business idea (no code needed yet)
✓ Willingness to think like a product owner, not a coder

The Core Philosophy

You are the product owner and technical director. The AI is your development team.

Documentation First

Never write code before documenting. Create business analysis, requirements, architecture, and agent orchestration rules before a single line of code.

Agent Teams, Not Solo

Define specialized agents (architects, devs, QA) with strict roles. Architects design, devs implement, QA verifies. No shortcuts.

Autonomous Execution

Once documentation and rules are in place, tell the AI to execute without waiting for approval. Trust the process, not each step.

The 8-Step Process

From business idea to deployed product, this is the exact sequence I follow.

1
1

Describe the Business Problem

Start by explaining the real-world problem in natural language. Don't mention technology. Describe the pain point, the users, the context, and the opportunity.

WHAT I TYPED

"We have this problem in our city: there's a huge gap between [service providers] and [customers]. The providers are hard to reach, and the customers need a way to access them conveniently. We want to build a platform that connects both sides through [delivery method]..."

Why it works: Claude analyzes the business domain, identifies actors (customers, providers, operators), understands constraints (payment methods, logistics, geographic limitations), and can then make informed architectural decisions.
2
2

Request Agent Orchestration Documentation

Before any code, ask Claude to create the rules for its own team. Define agent roles, the pipeline, and the unbreakable rules that prevent chaos.

WHAT I TYPED

"Crea documentacion para la orquestacion de agentes de IA que realizen el trabajo donde tendras varios arquitectos que validen cada paso, agents devs frontend y backend y automators en playwright. Esta orquestacion debe realizarse siempre para cada feature e implementacion y nunca evitar el uso de tu equipo de agentes."

CLAUDE GENERATES

Creates docs/06-AGENT-ORCHESTRATION.md with full pipeline definition, agent roles, prompt templates, and verification criteria.

3
3

Make Key Technical & UX Decisions

Feed critical constraints in short bursts. Each one becomes part of the permanent project memory (CLAUDE.md). These are the decisions that shape everything.

"Todo el sistema debe ser touch-first, mobile-first, progressive web app instalable en dispositivo movil"

"Tiene que tener una UI moderna con dark theme"

"Me pregunto si es mas eficiente tener toda la documentacion en ingles?"

Key insight: Each short message adds a constraint to the project. Claude incorporates them into the CLAUDE.md file which ALL agents read before doing work. This is how you enforce consistency across an AI team.
4
4

Invoke Architect Agents for Review

Ask the AI to spawn architect sub-agents that validate the documentation against business logic, technical feasibility, and UX principles.

WHAT I TYPED

"Levanta a tus arquitectos que revisen la documentacion y que agreguen cualquier mejora que vean necesario segun el negocio"

CLAUDE DOES

Spawns 3 parallel agents (Backend Architect, Frontend Architect, System Architect). They review all docs, add improvements, validate the color system for the target market, suggest security measures, and update documentation.

5
5

The Magic Prompt: Autonomous Execution

KEY MOMENT

This is where the real power is. Once docs are solid and agents are defined, you tell Claude to execute the entire plan without stopping for approval.

WHAT I TYPED

"Comenza todo el trabajo con tu equipo de agents sin parar, no esperes por mi aprobacion, continua y verifica cada paso con tus arquitectos y e2e tests"

What happens next:

  • ✓ Claude reads the sprint roadmap
  • ✓ For each sprint, spawns Architect agents (design phase)
  • ✓ Architects produce technical specs, Dev agents implement
  • ✓ QA agent writes Playwright E2E tests
  • ✓ System Architect validates integration
  • ✓ Moves to next sprint automatically
6
6

Occasional Nudges & Course Corrections

Sometimes the AI gets stuck or loses context (context window fills up). A short nudge gets it back on track.

"Continue, it seems you and your agents were stuck"

"Rise your architects and validate what other features we need for next iterations"

"Document, analyze, implement everything without waiting for me"

7

Infrastructure & Testing

Once features are implemented, ask about test infrastructure. The AI creates Docker test setups, CI/CD pipelines, and deployment configs.

"How can we test everything? Do you have a Docker compose infra?"

Result: Creates docker-compose.test.yml with databases in Docker, unit test scripts, Playwright E2E infrastructure, and separate test profiles.

8

Deployment Configuration

Describe your infrastructure constraints and let Claude build the entire deployment pipeline.

"Document the deployment in local and in [hosting platform]. This instance uses subdomains of [your-domain.com] and only uses port 443 via Cloudflare Tunnel. Create the docker-compose file."

Result: Production docker-compose with container registry images, CI/CD pipeline, nginx configs, Dockerfiles for frontend/backend, env templates, and full deployment docs.

The Secret Weapon: CLAUDE.md

The CLAUDE.md file at your project root is loaded into EVERY conversation. It's your team's constitution — the rules that all agents must follow, always.

CLAUDE.md 
# What goes in CLAUDE.md:

## Project Description
One paragraph explaining the business.

## Tech Stack
Exact versions, no ambiguity.

## Development Rules
- REST API with JSON responses
- Strict TypeScript in frontend
- Conventional Commits in English
- Mandatory tests for payment/order flows

## Language Policy
- UI: Spanish (hardcoded, no i18n)
- Code: English
- Docs: English

## UX Philosophy
Touch-first, mobile-first, PWA, dark theme...
(Include exact color codes, spacing, etc.)

## CRITICAL: Agent Orchestration
Every feature MUST go through the pipeline:
1. DESIGN → Architects (parallel)
2. IMPLEMENTATION → Devs (sequential)
3. TESTING → QA Automator
4. REVIEW → System Architect

### Unbreakable Rules:
- NEVER skip the pipeline
- NEVER implement without architect approval
- NEVER merge without E2E tests
- Architects DO NOT implement
- Backend ALWAYS before Frontend

Why this matters

When Claude Code spawns sub-agents, each one reads CLAUDE.md. This means your Backend Dev agent knows the color system. Your QA agent knows the business rules. Your Frontend agent knows it must be touch-first. It's a shared brain for the entire AI team.

Prompt Patterns That Work

These are the patterns I use repeatedly. Note: they're short. The magic is in the documentation, not the prompts.

Tell the problem like you're explaining it to a friend at a coffee shop. Include pain points, target users, and the business opportunity. No technical jargon.

"We have [problem] affecting [target users]. They need [solution] but there's no good way to access it. We want to build a platform that [value proposition]..."

Short, imperative constraints that become permanent rules. Each one shapes all future work.

"Must be a PWA installable on mobile"

"Dark theme, modern UI like Uber/Rappi"

"All UI in Spanish, code in English"

"Currency: [local currency], Timezone: [local TZ]"

Ask for review, not implementation. The architects catch issues before code is written.

"Rise your architects and validate the documentation"

"Have your architects analyze if the colors work for this market"

"Rise architects to see what features are missing for next iterations"

Once everything is documented and validated, give full autonomy. This is where hours of work happen with zero input from you.

"Start working with your agent team non-stop, don't wait for my approval"

"Document, analyze, implement everything without waiting for me"

"Continue without stopping, verify with architects and E2E tests"

Important: This only works AFTER solid documentation exists. Without CLAUDE.md and orchestration rules, autonomous execution produces garbage.

Describe your infrastructure constraints and let Claude figure out the how.

"Deploy on [platform], subdomains of [your-domain.com], only port 443 via Cloudflare Tunnel"

"I want GitHub Actions to build images and the hosting platform to consume them via webhook"

Pro Tips

1

Invest 80% in documentation, 20% in prompts

The better your CLAUDE.md and docs are, the less you need to type. A well-documented project runs on "continue" and "don't stop".

2

Use the agent pipeline as quality control

Having an "architect" review before a "dev" implements catches bad designs early. It's like mandatory code review but at the design level.

3

Context window is your enemy

Sessions will hit context limits and restart. That's fine — Claude reads CLAUDE.md on every new session. Your rules persist even when the conversation doesn't.

4

Be the product owner, not the developer

Think in terms of business requirements, constraints, and acceptance criteria. Let the AI decide HOW to implement. You decide WHAT and WHY.

5

Nudge, don't micromanage

If the AI gets stuck, a single sentence like "continue" or "you seem stuck" is enough. Don't re-explain the entire context — it already has it in the docs.

6

Memory system for cross-session continuity

Use "save your memory" to persist important decisions. Claude's memory system remembers your preferences, project context, and feedback across conversations.

Common Mistakes

×

Starting with code, not documentation

If you jump straight to "build me a login page", you get code without context. The AI will make random choices about architecture, testing, naming, etc. Documentation first = consistent output.

×

Giving autonomy without rules

Saying "build everything" without a CLAUDE.md is like hiring a team with no brief. They'll produce something, but it won't be what you wanted. Rules + autonomy = great results.

×

Micromanaging each step

If you approve every file, you lose the speed advantage. Trust the pipeline: architects validate design, devs implement, QA verifies. You only step in for business decisions.

×

Not enforcing the agent pipeline

Without the "NEVER skip the pipeline" rule in CLAUDE.md, the AI takes shortcuts. It will skip architect review, skip tests, and produce fragile code. The pipeline IS the quality.

×

Ignoring context window limits

Long sessions will hit the context limit and restart. If your rules only live in chat history, they're lost. Put everything in CLAUDE.md — it survives every restart.

Translating to Other AI Models

This methodology isn't locked to Claude. Here's how to apply the same orchestration process across different AI platforms.

GP

ChatGPT / OpenAI API

GPT-4o, o1, o3

System prompt = your CLAUDE.md (paste full content as system message)

Custom GPTs = define each agent as a separate Custom GPT with its own instructions

Assistants API = create assistants with tools for file I/O, code execution

Limitation: No native sub-agent spawning. You orchestrate manually or use LangGraph.

Cu

Cursor IDE

Agent mode

.cursorrules = your CLAUDE.md equivalent (same content, different filename)

Composer = multi-file implementation (like a Dev agent)

Agent mode = can run terminal commands, read files

Limitation: Single-agent only. No parallel architect/dev/QA pipeline natively.

Wi

Windsurf (Codeium)

Cascade agent

Rules file = place rules in project-level config

Cascade = multi-step agent with file access and terminal

Flows = predefined multi-step workflows

Limitation: Less control over agent separation. Better for single-dev workflows.

Ge

Google Gemini

Gemini 2.5 Pro, Flash

System instructions = your CLAUDE.md as system context

Gems = custom personas for each agent role

1M+ context = can hold entire codebase in one shot

Limitation: No native file system access or terminal. Needs wrapper tooling.

Key Takeaway

The methodology (documentation first → define agents → validate → execute autonomously) works everywhere. What changes is the mechanism: Claude Code has native multi-agent support; other tools require you to build the orchestration layer yourself or use frameworks like LangGraph.

Advanced: LangGraph, LangChain & LangSmith

ADVANCED

When to graduate from a single AI CLI to a programmatic orchestration framework — and how to translate this methodology into code.

When Do You Need This?

Claude Code CLI is enough when:

  • ✓ You're building a single product/project
  • ✓ One developer (you) orchestrating the AI
  • ✓ The pipeline runs in real-time during your session
  • ✓ Results are code commits, not API responses
  • ✓ Your agents don't need external data sources

Use LangGraph/LangChain when:

  • ● You need agents running 24/7 as a service
  • ● Multiple users trigger the same pipeline
  • ● Agents need to call external APIs, databases, or tools
  • ● You need observability, tracing, and cost tracking
  • ● You're building the product AS an AI agent system
  • ● You need human-in-the-loop approval gates in production

The LangChain Ecosystem

LC

LangChain — The building blocks

Library of components: LLM wrappers, prompt templates, document loaders, vector stores, tools. Use it to build individual agent capabilities (call APIs, search docs, parse files).

Maps to: Individual agent tools and capabilities (like how Claude Code can read files, run bash, search).

LG

LangGraph — The orchestration engine

A framework for building stateful, multi-agent workflows as directed graphs. Each node is an agent or tool, edges define the flow, and state persists across steps.

This is the programmatic equivalent of our entire orchestration methodology:

graph = StateGraph(OrchestratorState)

# Define agent nodes (same roles as our pipeline)
graph.add_node("architect_backend", architect_backend_agent)
graph.add_node("architect_frontend", architect_frontend_agent)
graph.add_node("dev_backend", dev_backend_agent)
graph.add_node("dev_frontend", dev_frontend_agent)
graph.add_node("qa_automator", qa_agent)
graph.add_node("system_review", system_architect_agent)

# Define the pipeline flow
graph.add_edge(START, "architect_backend")
graph.add_edge(START, "architect_frontend")  # parallel!
graph.add_edge("architect_backend", "dev_backend")
graph.add_edge("architect_frontend", "dev_frontend")
graph.add_edge("dev_backend", "qa_automator")
graph.add_edge("dev_frontend", "qa_automator")
graph.add_edge("qa_automator", "system_review")
graph.add_conditional_edges("system_review", approval_gate)

app = graph.compile(checkpointer=MemorySaver())

Maps to: The Orchestrator + entire agent pipeline (design → implement → test → review).

LS

LangSmith — Observability & debugging

Tracing platform that records every LLM call, tool invocation, and agent decision. Lets you debug why an agent made a bad choice, track costs, and evaluate quality over time.

Maps to: When you look at Claude Code's output and think "why did it do that?" — LangSmith gives you the full trace with token counts, latencies, and decision trees.

Architecture Comparison

Our CLI Approach (this guide)

You (human)
  │
  └─→ Claude Code CLI
        │
        ├─→ Architect Agent (subagent)
        ├─→ Dev Agent (subagent)
        ├─→ QA Agent (subagent)
        │
        └─→ Files on disk (your repo)

Trigger: your prompts
State: CLAUDE.md + files
Output: committed code

LangGraph Approach (programmatic)

API / Trigger / Cron
  │
  └─→ LangGraph Application
        │
        ├─→ Architect Node (LLM call)
        ├─→ Dev Node (LLM + tools)
        ├─→ QA Node (LLM + test runner)
        │
        └─→ External Systems (APIs, DBs)

Trigger: events / API calls
State: graph checkpointer
Output: API responses / actions

Combining Both Approaches

The most powerful setup uses both:

  • 1. Claude Code CLI for building the product itself — the methodology in this guide. Fast, interactive, great for greenfield development.
  • 2. LangGraph for building AI features INSIDE the product — if your product needs agent workflows (customer support bots, data processing pipelines, content generation).
  • 3. LangSmith for monitoring production AI — once your LangGraph agents are deployed, track their performance, cost, and quality.

Bottom Line

Use Claude Code CLI (this guide) to build software with AI as your dev team. Use LangGraph/LangChain when your software contains AI agents as a feature, or when you need unattended, production-grade orchestration running as a service. They solve different problems at different layers.
