Core Concepts Overview

LangChain v0.2+ is modular: langchain-core for abstractions, langchain-openai / langchain-anthropic for provider integrations, and langchain-community for third-party tools.

Models

LLMs and Chat Models. Unified interface to call OpenAI, Anthropic, local models, etc. All implement the .invoke() method.

Prompts

Templates that format inputs into messages. Support variables, few-shot examples, system instructions, and dynamic message lists.

Chains (LCEL)

LangChain Expression Language. Compose components with the pipe operator | into declarative pipelines with streaming, batching, and fallbacks.

Tools

Functions the LLM can call. Define with @tool decorator. Include description, args schema, and implementation.

Memory

Conversation history management. Buffer memory (keep all), summary memory (compress old), or custom strategies via RunnableWithMessageHistory.

Retrievers

Fetch relevant documents from vector stores, databases, or APIs. Used in RAG (Retrieval-Augmented Generation) pipelines for grounding LLM responses.

LCEL (LangChain Expression Language) lets you compose Runnables with the | pipe operator. Every component is a Runnable that supports .invoke(), .stream(), .batch(), and .ainvoke().

lcel_chains.py — Sequential, Parallel, and Branching 
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser, JsonOutputParser
from langchain_core.runnables import (
    RunnableParallel,
    RunnablePassthrough,
    RunnableLambda,
)
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o", temperature=0)


# --- Sequential Chain (Pipe Operator) ---
# Each step's output becomes the next step's input

summarize_prompt = ChatPromptTemplate.from_template(
    "Summarize this text in 2 sentences:\n\n{text}"
)

translate_prompt = ChatPromptTemplate.from_template(
    "Translate this English text to French:\n\n{text}"
)

# Chain: summarize → translate
summarize_chain = summarize_prompt | model | StrOutputParser()
translate_chain = translate_prompt | model | StrOutputParser()

# Compose them: output of summarize feeds into translate
full_chain = (
    summarize_prompt
    | model
    | StrOutputParser()
    | (lambda summary: {"text": summary})
    | translate_prompt
    | model
    | StrOutputParser()
)

result = full_chain.invoke({"text": "LangChain is a framework for..."})


# --- Parallel Chains (RunnableParallel) ---
# Run multiple chains simultaneously, combine results

analysis_chain = RunnableParallel(
    summary=summarize_prompt | model | StrOutputParser(),
    keywords=ChatPromptTemplate.from_template(
        "Extract 5 keywords from this text as a comma-separated list:\n\n{text}"
    ) | model | StrOutputParser(),
    sentiment=ChatPromptTemplate.from_template(
        "What is the sentiment of this text? Reply: positive, negative, or neutral.\n\n{text}"
    ) | model | StrOutputParser(),
)

# Returns a dict with all three results
results = analysis_chain.invoke({"text": "I love how easy LangChain makes it..."})
# {"summary": "...", "keywords": "...", "sentiment": "positive"}


# --- RunnablePassthrough (Pass data through unchanged) ---
# Useful for preserving the original input alongside transformations

chain_with_context = RunnableParallel(
    context=RunnableLambda(lambda x: fetch_docs(x["question"])),
    question=RunnablePassthrough(),
) | ChatPromptTemplate.from_template(
    "Context: {context}\n\nQuestion: {question}\n\nAnswer:"
) | model | StrOutputParser()


# --- RunnableLambda (Custom Functions in Chains) ---
# Wrap any Python function as a Runnable

def format_output(text: str) -> dict:
    """Custom processing step."""
    return {
        "content": text.strip(),
        "word_count": len(text.split()),
        "char_count": len(text),
    }

chain_with_processing = (
    summarize_prompt
    | model
    | StrOutputParser()
    | RunnableLambda(format_output)
)

result = chain_with_processing.invoke({"text": "Some long article..."})
# {"content": "...", "word_count": 42, "char_count": 231}

Key insight: Every LCEL chain automatically supports streaming, async, batching, and retry logic. You get production-grade behavior for free just by composing with |.

Tools let the LLM call external functions. Agents decide which tools to use and in what order, using a reasoning loop (ReAct pattern: Reason → Act → Observe → Repeat).

tools_and_agents.py — Complete agent with custom tools 
import os
from datetime import datetime
from typing import Optional

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain.agents import create_tool_calling_agent, AgentExecutor

load_dotenv()


# --- Define Custom Tools ---

@tool
def get_current_weather(city: str) -> str:
    """Get the current weather for a city. Returns temperature and conditions."""
    # In production, call a real weather API
    weather_data = {
        "London": "15°C, cloudy with light rain",
        "Tokyo": "28°C, sunny and humid",
        "New York": "22°C, partly cloudy",
    }
    return weather_data.get(city, f"Weather data not available for {city}")


@tool
def calculate(expression: str) -> str:
    """Evaluate a mathematical expression. Use Python math syntax.
    Examples: '2 + 2', '100 * 0.15', '(50 + 30) / 4'"""
    try:
        # Safe eval for math only
        allowed_names = {"__builtins__": {}}
        result = eval(expression, allowed_names)
        return str(result)
    except Exception as e:
        return f"Error: {e}"


@tool
def search_database(query: str, limit: Optional[int] = 5) -> str:
    """Search our product database. Returns matching products with prices.
    Args:
        query: Search term for products
        limit: Maximum number of results (default 5)
    """
    # Simulated database search
    products = [
        {"name": "Laptop Pro 16", "price": 1299, "stock": 15},
        {"name": "Wireless Mouse", "price": 49, "stock": 200},
        {"name": "USB-C Hub", "price": 79, "stock": 85},
    ]
    matches = [p for p in products if query.lower() in p["name"].lower()][:limit]
    if not matches:
        return "No products found matching your query."
    return "\n".join(f"{p['name']}: ${p['price']} ({p['stock']} in stock)" for p in matches)


# --- Create the Agent ---

# Collect tools
tools = [get_current_weather, calculate, search_database]

# Define the agent prompt
agent_prompt = ChatPromptTemplate.from_messages([
    ("system", """You are a helpful assistant with access to tools.
Use tools when needed to answer questions accurately.
Always show your reasoning before using a tool."""),
    MessagesPlaceholder(variable_name="chat_history", optional=True),
    ("human", "{input}"),
    MessagesPlaceholder(variable_name="agent_scratchpad"),
])

# Create the agent (uses tool-calling, not legacy OpenAI functions)
model = ChatOpenAI(model="gpt-4o", temperature=0)
agent = create_tool_calling_agent(model, tools, agent_prompt)

# Wrap in AgentExecutor (handles the ReAct loop)
agent_executor = AgentExecutor(
    agent=agent,
    tools=tools,
    verbose=True,  # Shows reasoning steps
    max_iterations=10,  # Safety limit
    handle_parsing_errors=True,
)

# --- Run the Agent ---

response = agent_executor.invoke({
    "input": "What's the weather in Tokyo? Also, if a laptop costs $1299 and I get 15% off, what's the final price?"
})

print(response["output"])
# The agent will:
# 1. Call get_current_weather("Tokyo") → "28°C, sunny and humid"
# 2. Call calculate("1299 * (1 - 0.15)") → "1104.15"
# 3. Combine both results into a natural language response

Key insight: The @tool decorator automatically generates a JSON schema from the function signature and docstring. Write clear docstrings — they are the tool's description that the LLM reads to decide when to use it.

Memory lets your chain remember previous interactions. The modern approach uses RunnableWithMessageHistory which integrates cleanly with LCEL chains and supports multiple session IDs.

memory_chain.py — Persistent conversation memory 
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_core.chat_history import BaseChatMessageHistory
from langchain_community.chat_message_histories import ChatMessageHistory

# --- In-Memory Store (use Redis/PostgreSQL in production) ---
store: dict[str, ChatMessageHistory] = {}


def get_session_history(session_id: str) -> BaseChatMessageHistory:
    """Retrieve or create chat history for a session."""
    if session_id not in store:
        store[session_id] = ChatMessageHistory()
    return store[session_id]


# --- Build the Chain ---
model = ChatOpenAI(model="gpt-4o", temperature=0.7)

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a friendly assistant. Remember details the user shares."),
    MessagesPlaceholder(variable_name="history"),
    ("human", "{input}"),
])

chain = prompt | model | StrOutputParser()

# --- Wrap with Message History ---
chain_with_history = RunnableWithMessageHistory(
    chain,
    get_session_history,
    input_messages_key="input",
    history_messages_key="history",
)

# --- Use It ---

# First message in session "user-123"
response1 = chain_with_history.invoke(
    {"input": "My name is Alice and I'm working on a Python project."},
    config={"configurable": {"session_id": "user-123"}},
)
print(response1)  # "Nice to meet you, Alice! Tell me about your Python project."

# Second message — it remembers!
response2 = chain_with_history.invoke(
    {"input": "What's my name and what am I working on?"},
    config={"configurable": {"session_id": "user-123"}},
)
print(response2)  # "Your name is Alice and you're working on a Python project!"

# Different session — fresh start
response3 = chain_with_history.invoke(
    {"input": "What's my name?"},
    config={"configurable": {"session_id": "user-456"}},
)
print(response3)  # "I don't know your name yet. What should I call you?"

# When conversations get too long, summarize older messages

from langchain_core.messages import SystemMessage, trim_messages

trimmer = trim_messages(
    max_tokens=1000,
    strategy="last",
    token_counter=model,
    include_system=True,
    allow_partial=False,
    start_on="human",

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_community.document_loaders import (
    PyPDFLoader,
    TextLoader,
    DirectoryLoader,
)
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough

load_dotenv()


# === STEP 1: Load Documents ===

# Load a single PDF
pdf_loader = PyPDFLoader("docs/company-handbook.pdf")
pdf_docs = pdf_loader.load()

# Load all .txt files from a directory
dir_loader = DirectoryLoader(
    "docs/",
    glob="**/*.txt",
    loader_cls=TextLoader,
)
txt_docs = dir_loader.load()

# Combine all documents
all_docs = pdf_docs + txt_docs
print(f"Loaded {len(all_docs)} document pages")


# === STEP 2: Split into Chunks ===

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=1000,       # Max characters per chunk
    chunk_overlap=200,     # Overlap between chunks for context
    length_function=len,
    separators=["\n\n", "\n", " ", ""],  # Split priority
)

chunks = text_splitter.split_documents(all_docs)
print(f"Split into {len(chunks)} chunks")


# === STEP 3: Embed & Store in Vector DB ===

embeddings = OpenAIEmbeddings(model="text-embedding-3-small")

# Create vector store (persisted to disk)
vectorstore = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    persist_directory="./chroma_db",
    collection_name="company_docs",
)

# Create a retriever (searches for top-k similar chunks)
retriever = vectorstore.as_retriever(
    search_type="similarity",
    search_kwargs={"k": 4},  # Return top 4 matches
)


# === STEP 4: Build the RAG Chain ===

rag_prompt = ChatPromptTemplate.from_template("""Answer the question based only on the following context. \
If you cannot find the answer in the context, say "I don't have enough information to answer that."

Context:
{context}

Question: {question}

Answer:""")


def format_docs(docs):
    """Format retrieved documents into a single string."""
    return "\n\n---\n\n".join(
        f"[Source: {doc.metadata.get('source', 'unknown')}]\n{doc.page_content}"
        for doc in docs
    )


model = ChatOpenAI(model="gpt-4o", temperature=0)

rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | rag_prompt
    | model
    | StrOutputParser()
)


# === STEP 5: Query ===

answer = rag_chain.invoke("What is our company's vacation policy?")
print(answer)

# With streaming:
for chunk in rag_chain.stream("How do I request time off?"):
    print(chunk, end="", flush=True)


# === BONUS: Load existing vector store (after first run) ===

# On subsequent runs, load from disk instead of re-embedding
existing_vectorstore = Chroma(
    persist_directory="./chroma_db",
    embedding_function=embeddings,
    collection_name="company_docs",
)
retriever = existing_vectorstore.as_retriever(search_kwargs={"k": 4})

Key insight: The chunk size and overlap are critical parameters. Too small and you lose context; too large and you waste tokens. Start with 1000/200 and tune based on your documents. Use RecursiveCharacterTextSplitter — it respects paragraph and sentence boundaries.

Documentation Q&A Bot
=====================
A conversational bot that answers questions about your documentation.
Features: RAG, conversation memory, streaming, source citations.

Usage:
    python doc_qa_bot.py --docs ./my-docs --query "How do I deploy?"
    python doc_qa_bot.py --docs ./my-docs --interactive
"""

import argparse
import os
from pathlib import Path

from dotenv import load_dotenv
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_chroma import Chroma
from langchain_community.document_loaders import (
    DirectoryLoader,
    TextLoader,
    PyPDFLoader,
    UnstructuredMarkdownLoader,
)
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_core.prompts import ChatPromptTemplate, MessagesPlaceholder
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnablePassthrough, RunnableLambda
from langchain_core.runnables.history import RunnableWithMessageHistory
from langchain_community.chat_message_histories import ChatMessageHistory
from langchain_core.documents import Document

load_dotenv()


# ============================================================
# Configuration
# ============================================================

CHROMA_DIR = "./chroma_db_docs"
COLLECTION_NAME = "documentation"
CHUNK_SIZE = 1200
CHUNK_OVERLAP = 200
RETRIEVAL_K = 5
MODEL_NAME = "gpt-4o"
EMBEDDING_MODEL = "text-embedding-3-small"


# ============================================================
# Document Loading & Indexing
# ============================================================

def load_documents(docs_path: str) -> list[Document]:
    """Load documents from a directory. Supports .txt, .md, .pdf."""
    docs_dir = Path(docs_path)
    if not docs_dir.exists():
        raise FileNotFoundError(f"Docs directory not found: {docs_path}")

    all_docs = []

    # Load Markdown files
    md_files = list(docs_dir.glob("**/*.md"))
    for md_file in md_files:
        loader = TextLoader(str(md_file), encoding="utf-8")
        all_docs.extend(loader.load())

    # Load text files
    txt_files = list(docs_dir.glob("**/*.txt"))
    for txt_file in txt_files:
        loader = TextLoader(str(txt_file), encoding="utf-8")
        all_docs.extend(loader.load())

    # Load PDFs
    pdf_files = list(docs_dir.glob("**/*.pdf"))
    for pdf_file in pdf_files:
        loader = PyPDFLoader(str(pdf_file))
        all_docs.extend(loader.load())

    print(f"  Loaded {len(all_docs)} document pages from {docs_path}")
    return all_docs


def create_vectorstore(docs: list[Document]) -> Chroma:
    """Split documents and create a Chroma vector store."""
    # Split into chunks
    splitter = RecursiveCharacterTextSplitter(
        chunk_size=CHUNK_SIZE,
        chunk_overlap=CHUNK_OVERLAP,
        separators=["\n## ", "\n### ", "\n\n", "\n", ". ", " "],
    )
    chunks = splitter.split_documents(docs)
    print(f"  Split into {len(chunks)} chunks")

    # Embed and store
    embeddings = OpenAIEmbeddings(model=EMBEDDING_MODEL)
    vectorstore = Chroma.from_documents(
        documents=chunks,
        embedding=embeddings,
        persist_directory=CHROMA_DIR,
        collection_name=COLLECTION_NAME,
    )
    print(f"  Vector store created at {CHROMA_DIR}")
    return vectorstore


def get_vectorstore() -> Chroma:
    """Load existing vector store from disk."""
    embeddings = OpenAIEmbeddings(model=EMBEDDING_MODEL)
    return Chroma(
        persist_directory=CHROMA_DIR,
        embedding_function=embeddings,
        collection_name=COLLECTION_NAME,
    )


# ============================================================
# QA Chain with Memory
# ============================================================

# Session store
_session_store: dict[str, ChatMessageHistory] = {}


def get_session_history(session_id: str) -> ChatMessageHistory:
    if session_id not in _session_store:
        _session_store[session_id] = ChatMessageHistory()
    return _session_store[session_id]


def build_qa_chain(vectorstore: Chroma):
    """Build the full QA chain with RAG and memory."""

    retriever = vectorstore.as_retriever(
        search_type="similarity",
        search_kwargs={"k": RETRIEVAL_K},
    )

    # Contextualize the question using chat history
    contextualize_prompt = ChatPromptTemplate.from_messages([
        ("system", """Given the chat history and the latest user question, \
reformulate the question to be standalone (understandable without history). \
Do NOT answer the question. Only reformulate if needed, otherwise return as-is."""),
        MessagesPlaceholder(variable_name="chat_history"),
        ("human", "{input}"),
    ])

    model = ChatOpenAI(model=MODEL_NAME, temperature=0)

    # Chain to reformulate question with context
    contextualize_chain = contextualize_prompt | model | StrOutputParser()

    # The main QA prompt
    qa_prompt = ChatPromptTemplate.from_messages([
        ("system", """You are a documentation assistant. Answer questions using ONLY \
the provided context. If the answer is not in the context, say so clearly.

Rules:
- Be concise and direct
- Quote relevant parts of the documentation when helpful
- If you cite a source, mention the file name
- Format code snippets with backticks

Context:
{context}"""),
        MessagesPlaceholder(variable_name="chat_history"),
        ("human", "{input}"),
    ])

    def format_docs(docs: list[Document]) -> str:
        formatted = []
        for doc in docs:
            source = Path(doc.metadata.get("source", "unknown")).name
            formatted.append(f"[{source}]\n{doc.page_content}")
        return "\n\n---\n\n".join(formatted)

    def contextualized_retrieval(input_dict: dict) -> str:
        """Reformulate question if there's history, then retrieve."""
        chat_history = input_dict.get("chat_history", [])
        question = input_dict["input"]

        # If there's history, reformulate the question
        if chat_history:
            question = contextualize_chain.invoke({
                "input": question,
                "chat_history": chat_history,
            })

        # Retrieve relevant documents
        docs = retriever.invoke(question)
        return format_docs(docs)

    # Full chain
    chain = (
        RunnablePassthrough.assign(
            context=RunnableLambda(contextualized_retrieval)
        )
        | qa_prompt
        | model
        | StrOutputParser()
    )

    # Wrap with message history
    chain_with_history = RunnableWithMessageHistory(
        chain,
        get_session_history,
        input_messages_key="input",
        history_messages_key="chat_history",
    )

    return chain_with_history

LangGraph Deep Dive

Build stateful, multi-actor AI applications as directed graphs. From simple chains to complex multi-agent orchestrations with human-in-the-loop control.

1

What is LangGraph?

LangGraph is a framework for building stateful, multi-actor applications with LLMs, structured as computational graphs. Unlike simple chain-based approaches, LangGraph gives you:

  • ▶ Cycles & Loops — Agents can iterate, retry, and self-correct
  • ▶ Persistent State — Memory survives across interactions via checkpoints
  • ▶ Human-in-the-Loop — Pause execution, get approval, resume
  • ▶ Multi-Agent — Multiple specialized agents collaborating

LangGraph vs LangChain Agents

Feature LangChain Agents LangGraph
Control Flow LLM decides You define the graph
State Limited Full TypedDict state
Cycles ReAct loop only Arbitrary cycles
Multi-Agent Manual wiring Native support
Persistence External Built-in checkpoints
2

Core Concepts

📊

StateGraph

The container that holds your entire graph definition. You add nodes and edges to it, then compile.

⚫

Nodes

Python functions that receive state, perform work (LLM calls, tools, logic), and return state updates.

➔

Edges

Connections between nodes. Define the execution flow — which node runs after which.

🔀

Conditional Edges

Routing functions that examine state and decide which node executes next. Enables branching logic.

🗃

State (TypedDict)

A typed dictionary that flows through the graph. Each node reads and writes to it. Supports reducers for accumulation.

💾

Checkpoints

Snapshots of state at each step. Enable persistence, time-travel, and human-in-the-loop interrupts.

How It Flows Together


    ┌─────────┐
    │  START  │
    └────┬────┘
         │
         ▼
    ┌─────────┐      State: { messages: [], step: 0 }
    │ Node A  │──────────────────────────────────────▶ Reads state, does work, returns updates
    └────┬────┘
         │
         ▼
    ┌──────────────┐
    │ Conditional  │──── if state["needs_review"] ──▶ Node C (Review)
    │    Edge      │
    └──────┬───────┘
           │ else
           ▼
    ┌─────────┐
    │ Node B  │──────────────────────────────────────▶ Final processing
    └────┬────┘
         │
         ▼
    ┌─────────┐
    │   END   │      Checkpoint saved at each step!
    └─────────┘

Step 1: Your First Graph

Let's build a simple two-node graph that takes a topic, generates a joke about it, then rates the joke. This shows the fundamental pattern: define state, create nodes, wire edges, compile, invoke. 

from typing import TypedDict

Step 2: State Management

State is the backbone of LangGraph. It's a TypedDict that flows through every node. The key insight: nodes return partial updates, not the full state. LangGraph merges updates intelligently.

Default Behavior (Overwrite)

By default, returning a key overwrites the previous value.

class State(TypedDict):
    query: str       # Overwritten each time
    answer: str      # Overwritten each time

# Node returns {"answer": "new"}
# -> state["answer"] becomes "new"

Reducer Behavior (Accumulate)

Use Annotated with a reducer to accumulate values.

from typing import Annotated
import operator

class State(TypedDict):
    messages: Annotated[list, operator.add]

# Node returns {"messages": ["new msg"]}
# -> appends to existing list!

Multi-Step Research Agent State

from typing import TypedDict, Annotated, Literal
import operator
from langgraph.graph import StateGraph, START, END

class ResearchState(TypedDict):
    # The original research question
    question: str
    # Search queries generated (accumulates via reducer)
    search_queries: Annotated[list[str], operator.add]
    # Raw search results (accumulates)
    search_results: Annotated[list[dict], operator.add]
    # Refined analysis at each step (overwrites)
    current_analysis: str
    # Number of research iterations completed
    iteration: int
    # Final synthesized answer
    final_answer: str

def plan_searches(state: ResearchState) -> dict:
    """Generate search queries based on the question and current analysis."""
    # LLM generates 2-3 search queries
    queries = generate_search_queries(state["question"], state.get("current_analysis", ""))
    return {
        "search_queries": queries,  # Appended to list!
        "iteration": state.get("iteration", 0) + 1  # Overwrites
    }

def execute_searches(state: ResearchState) -> dict:
    """Run the latest search queries and collect results."""
    latest_queries = state["search_queries"][-3:]  # Last 3 queries
    results = [search(q) for q in latest_queries]
    return {"search_results": results}  # Appended to list!

def analyze(state: ResearchState) -> dict:
    """Synthesize all results into current analysis."""
    analysis = llm.invoke(
        f"Analyze these results for: {state['question']}\n"
        f"Results: {state['search_results']}"
    )
    return {"current_analysis": analysis.content}  # Overwrites!

def synthesize(state: ResearchState) -> dict:
    """Create the final answer from all research."""
    answer = llm.invoke(
        f"Final answer for: {state['question']}\n"
        f"Based on analysis: {state['current_analysis']}"
    )
    return {"final_answer": answer.content}

# Build graph
graph = StateGraph(ResearchState)
graph.add_node("plan", plan_searches)
graph.add_node("search", execute_searches)
graph.add_node("analyze", analyze)
graph.add_node("synthesize", synthesize)

graph.add_edge(START, "plan")
graph.add_edge("plan", "search")
graph.add_edge("search", "analyze")
# After analysis, decide: research more or synthesize
graph.add_conditional_edges("analyze", should_continue, {"continue": "plan", "done": "synthesize"})
graph.add_edge("synthesize", END)

app = graph.compile()

Key Insight: With Annotated[list, operator.add], every node's list return gets appended to the existing state — perfect for accumulating messages, search results, or history. Without the annotation, the list would be replaced entirely.

Step 3: Conditional Routing

Conditional edges are where LangGraph becomes powerful. Instead of a fixed path, a routing function examines the current state and decides which node runs next. This enables agents that adapt their behavior dynamically.

How It Works

  1. 1. A node finishes execution and updates state
  2. 2. LangGraph calls your routing function with the current state
  3. 3. The routing function returns a string — the name of the next node
  4. 4. LangGraph routes execution to that node
from typing import TypedDict, Literal, Annotated
import operator
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

class AgentState(TypedDict):
    query: str
    messages: Annotated[list, operator.add]
    intent: str
    result: str

llm = ChatOpenAI(model="gpt-4o-mini")

# --- Nodes ---
def classify_intent(state: AgentState) -> dict:
    """Classify user query into: search, calculate, or respond."""
    response = llm.invoke(
        f"Classify this query into exactly one category: 'search', 'calculate', or 'respond'.\n"
        f"Query: {state['query']}\n"
        f"Return ONLY the category word."
    )
    intent = response.content.strip().lower()
    return {"intent": intent, "messages": [f"Classified as: {intent}"]}

def search_node(state: AgentState) -> dict:
    """Handle search-type queries."""
    result = llm.invoke(f"Search and answer: {state['query']}")
    return {"result": result.content, "messages": ["Executed search"]}

def calculate_node(state: AgentState) -> dict:
    """Handle calculation queries."""
    result = llm.invoke(f"Calculate and explain: {state['query']}")
    return {"result": result.content, "messages": ["Executed calculation"]}

def respond_node(state: AgentState) -> dict:
    """Handle general conversation."""
    result = llm.invoke(f"Respond conversationally: {state['query']}")
    return {"result": result.content, "messages": ["Generated response"]}

# --- Routing Function ---
def route_by_intent(state: AgentState) -> Literal["search", "calculate", "respond"]:
    """Route to the appropriate node based on classified intent."""
    return state["intent"]

# --- Build Graph ---
graph = StateGraph(AgentState)

graph.add_node("classify", classify_intent)
graph.add_node("search", search_node)
graph.add_node("calculate", calculate_node)
graph.add_node("respond", respond_node)

graph.add_edge(START, "classify")

# Conditional routing after classification
graph.add_conditional_edges(
    "classify",              # Source node
    route_by_intent,         # Routing function
    {                        # Mapping: return value -> node name
        "search": "search",
        "calculate": "calculate",
        "respond": "respond",
    }
)

# All paths lead to END
graph.add_edge("search", END)
graph.add_edge("calculate", END)
graph.add_edge("respond", END)

app = graph.compile()

# Test it
result = app.invoke({"query": "What is 15% of 230?", "messages": []})
print(result["intent"])   # "calculate"
print(result["result"])   # "15% of 230 is 34.5..."

Step 4: Human-in-the-Loop

LangGraph can pause execution at any node, wait for human input or approval, then resume exactly where it left off. This is powered by checkpointing — the entire state is saved, so the graph can be resumed later (even in a different process).

interrupt_before

Pause before a node executes. Human can modify state or approve.

interrupt_after

Pause after a node executes. Human can review output before continuing.

MemorySaver

In-memory checkpointer that saves state for resumption. Use DB savers in production.

from typing import TypedDict, Annotated, Literal
import operator
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI

class ContentState(TypedDict):
    topic: str
    draft: str
    feedback: str
    approved: bool
    final_content: str
    messages: Annotated[list[str], operator.add]

llm = ChatOpenAI(model="gpt-4o")

def generate_draft(state: ContentState) -> dict:
    """AI generates content draft."""
    response = llm.invoke(
        f"Write a blog post draft about: {state['topic']}\n"
        f"Previous feedback: {state.get('feedback', 'None')}"
    )
    return {
        "draft": response.content,
        "messages": ["Draft generated - awaiting human review"]
    }

def revise_draft(state: ContentState) -> dict:
    """Revise based on human feedback."""
    response = llm.invoke(
        f"Revise this draft based on feedback.\n"
        f"Draft: {state['draft']}\n"
        f"Feedback: {state['feedback']}"
    )
    return {
        "draft": response.content,
        "messages": ["Draft revised based on feedback"]
    }

def publish(state: ContentState) -> dict:
    """Publish the approved content."""
    return {
        "final_content": state["draft"],
        "messages": ["Content published!"]
    }

def check_approval(state: ContentState) -> Literal["publish", "revise"]:
    """Route based on human approval."""
    if state.get("approved", False):
        return "publish"
    return "revise"

# Build graph
graph = StateGraph(ContentState)
graph.add_node("generate", generate_draft)
graph.add_node("revise", revise_draft)
graph.add_node("publish", publish)

graph.add_edge(START, "generate")
# After generate, pause for human review (interrupt_after)
graph.add_conditional_edges("generate", check_approval, {"publish": "publish", "revise": "revise"})
graph.add_conditional_edges("revise", check_approval, {"publish": "publish", "revise": "revise"})
graph.add_edge("publish", END)

# Compile with checkpointer and interrupt
checkpointer = MemorySaver()
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_after=["generate", "revise"]  # Pause after these nodes
)

# --- Usage Flow ---
config = {"configurable": {"thread_id": "content-review-1"}}

# Step 1: Start the graph (will pause after "generate")
result = app.invoke({"topic": "AI in Healthcare", "messages": []}, config)
print("DRAFT:", result["draft"][:200], "...")
print("--- Graph paused. Awaiting human review. ---")

# Step 2: Human reviews and provides feedback
# Update state with human input, then resume
app.update_state(config, {
    "feedback": "Make it more technical, add specific examples of AI diagnostics",
    "approved": False
})
result = app.invoke(None, config)  # Resume! (pass None to continue)
print("REVISED:", result["draft"][:200], "...")

# Step 3: Human approves
app.update_state(config, {"approved": True})
result = app.invoke(None, config)  # Resume -> goes to "publish"
print("PUBLISHED:", result["final_content"][:200])

Production Tip: In a real app, the thread_id would be stored in your database. When the human submits their review via a web form, your API endpoint would load the thread, call update_state(), then invoke(None, config) to resume.

Step 5: Multi-Agent Patterns

The Supervisor Pattern is the most common multi-agent architecture. One "supervisor" agent decides which specialist agent should work next, creating a team of focused agents that collaborate.

Supervisor Architecture


                    ┌──────────────┐
                    │  Supervisor  │ ◄── Decides who works next
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              │            │            │
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │ Research │ │  Writer  │ │ Reviewer │
        │  Agent   │ │  Agent   │ │  Agent   │
        └──────────┘ └──────────┘ └──────────┘
              │            │            │
              └────────────┼────────────┘
                           │
                           ▼
                    ┌──────────────┐
                    │   FINISH     │
                    └──────────────┘

from typing import TypedDict, Annotated, Literal
import operator
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

class TeamState(TypedDict):
    task: str
    messages: Annotated[list[str], operator.add]
    research: str
    draft: str
    review: str
    next_agent: str
    iterations: int

llm = ChatOpenAI(model="gpt-4o")

# --- Supervisor ---
def supervisor(state: TeamState) -> dict:
    """Decide which agent should work next."""
    response = llm.invoke(
        f"You are a project supervisor. Given the current state, decide who works next.\n"
        f"Task: {state['task']}\n"
        f"Research done: {'Yes' if state.get('research') else 'No'}\n"
        f"Draft written: {'Yes' if state.get('draft') else 'No'}\n"
        f"Review done: {'Yes' if state.get('review') else 'No'}\n"
        f"Iterations: {state.get('iterations', 0)}\n\n"
        f"Choose exactly one: 'researcher', 'writer', 'reviewer', or 'FINISH'\n"
        f"Return ONLY the choice."
    )
    next_agent = response.content.strip().lower()
    return {"next_agent": next_agent, "messages": [f"Supervisor -> {next_agent}"]}

# --- Specialist Agents ---
def researcher(state: TeamState) -> dict:
    """Research agent gathers information."""
    response = llm.invoke(
        f"You are a research specialist. Research this topic thoroughly:\n{state['task']}"
    )
    return {
        "research": response.content,
        "messages": ["Research completed"]
    }

def writer(state: TeamState) -> dict:
    """Writer agent creates content based on research."""
    response = llm.invoke(
        f"You are a professional writer. Write content based on:\n"
        f"Task: {state['task']}\n"
        f"Research: {state['research']}\n"
        f"Previous review feedback: {state.get('review', 'None')}"
    )
    return {
        "draft": response.content,
        "iterations": state.get("iterations", 0) + 1,
        "messages": ["Draft written"]
    }

def reviewer(state: TeamState) -> dict:
    """Reviewer agent evaluates the draft."""
    response = llm.invoke(
        f"You are a critical reviewer. Review this draft:\n{state['draft']}\n\n"
        f"Provide specific feedback or say 'APPROVED' if it's ready."
    )
    return {"review": response.content, "messages": ["Review completed"]}

# --- Routing ---
def route_supervisor(state: TeamState) -> Literal["researcher", "writer", "reviewer", "FINISH"]:
    return state["next_agent"]

# --- Build Graph ---
graph = StateGraph(TeamState)

graph.add_node("supervisor", supervisor)
graph.add_node("researcher", researcher)
graph.add_node("writer", writer)
graph.add_node("reviewer", reviewer)

graph.add_edge(START, "supervisor")

graph.add_conditional_edges("supervisor", route_supervisor, {
    "researcher": "researcher",
    "writer": "writer",
    "reviewer": "reviewer",
    "FINISH": END,
})

# All agents report back to supervisor
graph.add_edge("researcher", "supervisor")
graph.add_edge("writer", "supervisor")
graph.add_edge("reviewer", "supervisor")

app = graph.compile()

# Run it
result = app.invoke({
    "task": "Write a technical blog post about WebSocket scaling strategies",
    "messages": [],
    "iterations": 0
})

print("Messages (flow):", result["messages"])
print("\nFinal Draft:", result["draft"][:500])

Step 6: Subgraphs

Subgraphs let you compose complex systems from smaller, reusable graph modules. A parent graph can invoke a child graph as if it were a single node — perfect for encapsulating team workflows.

Why Subgraphs?

  • • Modularity — Each team/workflow is self-contained and testable independently
  • • Reusability — Same subgraph can be used in multiple parent graphs
  • • State Isolation — Subgraph has its own state schema; only mapped fields cross boundaries
  • • Hierarchical Teams — A supervisor can delegate to an entire team (subgraph), not just one agent 
from typing import TypedDict, Annotated, Literal
import operator
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o")

# ============================================================
# SUBGRAPH: Code Review Team
# ============================================================
class ReviewState(TypedDict):
    code: str
    review_comments: Annotated[list[str], operator.add]
    security_passed: bool
    style_passed: bool
    approved: bool

def security_review(state: ReviewState) -> dict:
    """Check code for security issues."""
    response = llm.invoke(
        f"Review this code for security vulnerabilities. "
        f"Reply 'PASS' or describe issues:\n{state['code']}"
    )
    passed = "pass" in response.content.lower()
    return {
        "security_passed": passed,
        "review_comments": [f"Security: {response.content}"]
    }

def style_review(state: ReviewState) -> dict:
    """Check code style and best practices."""
    response = llm.invoke(
        f"Review code style and best practices. "
        f"Reply 'PASS' or describe issues:\n{state['code']}"
    )
    passed = "pass" in response.content.lower()
    return {
        "style_passed": passed,
        "review_comments": [f"Style: {response.content}"]
    }

def review_decision(state: ReviewState) -> dict:
    """Final review decision based on all checks."""
    approved = state.get("security_passed", False) and state.get("style_passed", False)
    return {
        "approved": approved,
        "review_comments": [f"Final decision: {'APPROVED' if approved else 'REJECTED'}"]
    }

# Build the review subgraph
review_graph = StateGraph(ReviewState)
review_graph.add_node("security", security_review)
review_graph.add_node("style", style_review)
review_graph.add_node("decision", review_decision)

graph.add_edge(START, "security")
review_graph.add_edge(START, "security")
review_graph.add_edge("security", "style")
review_graph.add_edge("style", "decision")
review_graph.add_edge("decision", END)

compiled_review = review_graph.compile()

# ============================================================
# PARENT GRAPH: Development Pipeline
# ============================================================
class DevState(TypedDict):
    requirement: str
    design: str
    code: str
    review_result: str
    review_approved: bool
    messages: Annotated[list[str], operator.add]

def design_phase(state: DevState) -> dict:
    """Architect designs the solution."""
    response = llm.invoke(
        f"Design a solution for: {state['requirement']}\n"
        f"Provide architecture and approach."
    )
    return {"design": response.content, "messages": ["Design completed"]}

def coding_phase(state: DevState) -> dict:
    """Developer implements the design."""
    response = llm.invoke(
        f"Implement this design in Python:\n{state['design']}"
    )
    return {"code": response.content, "messages": ["Code written"]}

def code_review_phase(state: DevState) -> dict:
    """Invoke the review subgraph."""
    # Run the compiled review subgraph
    review_result = compiled_review.invoke({
        "code": state["code"],
        "review_comments": []
    })
    return {
        "review_result": "\n".join(review_result["review_comments"]),
        "review_approved": review_result["approved"],
        "messages": ["Code review completed"]
    }

def deploy_phase(state: DevState) -> dict:
    """Deploy the approved code."""
    return {"messages": ["Code deployed successfully!"]}

def fix_code(state: DevState) -> dict:
    """Fix code based on review feedback."""
    response = llm.invoke(
        f"Fix this code based on review feedback:\n"
        f"Code: {state['code']}\n"
        f"Feedback: {state['review_result']}"
    )
    return {"code": response.content, "messages": ["Code fixed based on review"]}

def route_after_review(state: DevState) -> Literal["deploy", "fix"]:
    return "deploy" if state["review_approved"] else "fix"

# Build parent graph
parent_graph = StateGraph(DevState)
parent_graph.add_node("design", design_phase)
parent_graph.add_node("code", coding_phase)
parent_graph.add_node("review", code_review_phase)
parent_graph.add_node("deploy", deploy_phase)
parent_graph.add_node("fix", fix_code)

parent_graph.add_edge(START, "design")
parent_graph.add_edge("design", "code")
parent_graph.add_edge("code", "review")
parent_graph.add_conditional_edges("review", route_after_review, {
    "deploy": "deploy",
    "fix": "fix"

parent_graph.add_edge("deploy", END)

Step 7: Streaming

LangGraph supports streaming graph execution in real-time. Instead of waiting for the entire graph to finish, you can observe state updates as each node completes — critical for responsive UIs.

stream_mode="values"

Emits the full state after each node completes. Best for debugging.

stream_mode="updates"

Emits only the state delta (what changed). Efficient for large states.

stream_mode="messages"

Streams LLM tokens as they're generated. Best for chat UIs.

from typing import TypedDict, Annotated
import operator
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

class StreamState(TypedDict):
    topic: str
    outline: str
    content: str
    messages: Annotated[list[str], operator.add]

llm = ChatOpenAI(model="gpt-4o-mini", streaming=True)

def create_outline(state: StreamState) -> dict:
    response = llm.invoke(f"Create a brief outline for: {state['topic']}")
    return {"outline": response.content, "messages": ["Outline created"]}

def write_content(state: StreamState) -> dict:
    response = llm.invoke(f"Write content based on this outline:\n{state['outline']}")
    return {"content": response.content, "messages": ["Content written"]}

graph = StateGraph(StreamState)
graph.add_node("outline", create_outline)
graph.add_node("write", write_content)
graph.add_edge(START, "outline")
graph.add_edge("outline", "write")
graph.add_edge("write", END)

app = graph.compile()

# --- Streaming: values mode (full state after each node) ---
print("=== Stream Mode: values ===")
for state_snapshot in app.stream(
    {"topic": "Quantum Computing", "messages": []},
    stream_mode="values"
):
    print(f"State keys updated: {list(state_snapshot.keys())}")

# --- Streaming: updates mode (only deltas) ---
print("\n=== Stream Mode: updates ===")
for node_name, update in app.stream(
    {"topic": "Quantum Computing", "messages": []},
    stream_mode="updates"
):
    print(f"Node '{node_name}' produced: {list(update.keys())}")

import asyncio

async def stream_tokens():
    print("\n=== Async Stream: messages (token-by-token) ===")

        {"topic": "Quantum Computing", "messages": []},

Step 8: Persistence & Time-Travel

Checkpointers save the graph state after every node execution. This enables: resuming interrupted workflows, conversation memory across sessions, and time-travel debugging — replaying execution from any previous checkpoint.

Available Checkpointers

  • MemorySaver — In-memory, great for dev/testing
  • SqliteSaver — File-based, good for local persistence
  • PostgresSaver — Production-ready, scalable

Time-Travel Debugging

Every checkpoint stores:

  • • Full state at that point
  • • Which node just executed
  • • Parent checkpoint reference
  • • Timestamp and metadata

You can "rewind" to any checkpoint and re-execute with different inputs.

from typing import TypedDict, Annotated
import operator
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, BaseMessage

class ConversationState(TypedDict):
    messages: Annotated[list[BaseMessage], operator.add]
    summary: str

llm = ChatOpenAI(model="gpt-4o-mini")

def chatbot(state: ConversationState) -> dict:
    """Process the conversation and generate a response."""
    # Include summary for context if conversation is long
    system_msg = ""
    if state.get("summary"):
        system_msg = f"Previous conversation summary: {state['summary']}\n\n"

    response = llm.invoke(
        system_msg + "\n".join([
            f"{'Human' if isinstance(m, HumanMessage) else 'AI'}: {m.content}"
            for m in state["messages"][-10:]  # Last 10 messages for context window
        ])
    )
    return {"messages": [AIMessage(content=response.content)]}

def should_summarize(state: ConversationState) -> str:
    """Summarize if conversation is getting long."""
    if len(state["messages"]) > 20:
        return "summarize"
    return "end"

def summarize_conversation(state: ConversationState) -> dict:
    """Compress older messages into a summary."""
    old_messages = state["messages"][:-10]
    summary_prompt = (
        f"Summarize this conversation:\n"
        + "\n".join([f"{type(m).__name__}: {m.content}" for m in old_messages])
    )
    response = llm.invoke(summary_prompt)
    return {"summary": response.content}

# Build graph
graph = StateGraph(ConversationState)
graph.add_node("chatbot", chatbot)
graph.add_node("summarize", summarize_conversation)

graph.add_edge(START, "chatbot")
graph.add_conditional_edges("chatbot", should_summarize, {
    "summarize": "summarize",
    "end": END
})
graph.add_edge("summarize", END)

# Compile with persistence
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

# --- Conversation Session 1 ---
config = {"configurable": {"thread_id": "user-123-session"}}

# First message
result = app.invoke(
    {"messages": [HumanMessage(content="Hi! I'm working on a Python project.")]},
    config
)
print("AI:", result["messages"][-1].content)

# Second message (state is persisted!)
result = app.invoke(
    {"messages": [HumanMessage(content="I need help with async programming.")]},
    config
)
print("AI:", result["messages"][-1].content)

# --- Time Travel: View all checkpoints ---
print("\n=== Checkpoint History ===")
for checkpoint in app.get_state_history(config):
    print(f"  Step: {checkpoint.metadata.get('step', '?')} | "
          f"Messages: {len(checkpoint.values.get('messages', []))} | "
          f"ID: {checkpoint.config['configurable']['checkpoint_id'][:8]}...")

# --- Time Travel: Replay from an earlier checkpoint ---
history = list(app.get_state_history(config))
if len(history) >= 2:
    old_checkpoint = history[-2]  # Go back to first interaction
    replay_config = old_checkpoint.config

    # Resume from that point with a different message
    result = app.invoke(
        {"messages": [HumanMessage(content="Actually, help me with databases instead.")]},
        replay_config
    )
    print("\nAlternate timeline AI:", result["messages"][-1].content)

from typing import TypedDict, Annotated, Literal
import operator
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langchain_openai import ChatOpenAI

# === State Definition ===
class DevTeamState(TypedDict):
    requirement: str
    architecture: str
    code: str
    review_feedback: str
    review_passed: bool
    human_approved: bool
    deploy_status: str
    iteration_count: int
    messages: Annotated[list[str], operator.add]

llm = ChatOpenAI(model="gpt-4o")

# === Agent Nodes ===
def architect_agent(state: DevTeamState) -> dict:
    """Architect designs the technical solution."""
    feedback_context = ""
    if state.get("review_feedback"):
        feedback_context = f"\nAddress this review feedback in your design: {state['review_feedback']}"

    response = llm.invoke(
        f"You are a senior software architect. Design a solution for:\n"
        f"{state['requirement']}\n{feedback_context}\n\n"
        f"Provide: 1) Architecture overview 2) Key components 3) Data flow 4) Tech decisions"
    )
    return {
        "architecture": response.content,
        "messages": [f"[Architect] Solution designed (iteration {state.get('iteration_count', 0) + 1})"]
    }

def developer_agent(state: DevTeamState) -> dict:
    """Developer implements the architecture."""
    response = llm.invoke(
        f"You are a senior developer. Implement this architecture in Python:\n"
        f"Architecture: {state['architecture']}\n"
        f"Requirement: {state['requirement']}\n\n"
        f"Write clean, production-ready code with type hints and docstrings."
    )
    return {
        "code": response.content,
        "iteration_count": state.get("iteration_count", 0) + 1,
        "messages": ["[Developer] Code implemented"]
    }

def reviewer_agent(state: DevTeamState) -> dict:
    """Reviewer evaluates code quality, can reject."""
    response = llm.invoke(
        f"You are a strict code reviewer. Review this code:\n"
        f"{state['code']}\n\n"
        f"Check for: bugs, security issues, performance, best practices.\n"
        f"Start your response with 'APPROVED:' or 'REJECTED:' followed by detailed feedback."
    )
    content = response.content
    passed = content.upper().startswith("APPROVED")
    return {
        "review_feedback": content,
        "review_passed": passed,
        "messages": [f"[Reviewer] {'APPROVED' if passed else 'REJECTED'}: {content[:100]}..."]
    }

def deploy_agent(state: DevTeamState) -> dict:
    """Deploy the approved code."""
    return {
        "deploy_status": "deployed_successfully",
        "messages": ["[Deploy] Code deployed to production!"]
    }

# === Routing Functions ===
def route_after_review(state: DevTeamState) -> Literal["deploy_gate", "architect"]:
    """After review: if passed go to deploy gate, else back to architect."""
    if state["review_passed"]:
        return "deploy_gate"
    # Limit iterations to prevent infinite loops
    if state.get("iteration_count", 0) >= 3:
        return "deploy_gate"  # Force through after 3 attempts
    return "architect"

def route_after_human(state: DevTeamState) -> Literal["deploy", "architect"]:
    """After human review: deploy or send back for rework."""
    if state.get("human_approved", False):
        return "deploy"
    return "architect"

def deploy_gate(state: DevTeamState) -> dict:
    """Gate node before deployment - human will review here."""
    return {
        "messages": ["[Gate] Code review passed. Awaiting human approval for deployment."]
    }

# === Build the Graph ===
graph = StateGraph(DevTeamState)

# Add all nodes
graph.add_node("architect", architect_agent)
graph.add_node("developer", developer_agent)
graph.add_node("reviewer", reviewer_agent)
graph.add_node("deploy_gate", deploy_gate)
graph.add_node("deploy", deploy_agent)

# Define edges
graph.add_edge(START, "architect")
graph.add_edge("architect", "developer")
graph.add_edge("developer", "reviewer")

# Conditional: after review
graph.add_conditional_edges("reviewer", route_after_review, {
    "deploy_gate": "deploy_gate",
    "architect": "architect"
})

# Conditional: after human approval
graph.add_conditional_edges("deploy_gate", route_after_human, {
    "deploy": "deploy",
    "architect": "architect"
})

graph.add_edge("deploy", END)

# === Compile with checkpointer and human interrupt ===
checkpointer = MemorySaver()
app = graph.compile(
    checkpointer=checkpointer,
    interrupt_after=["deploy_gate"]  # Pause for human approval
)

# === Run the Pipeline ===
config = {"configurable": {"thread_id": "feature-auth-jwt-001"}}

# Start execution (will pause at deploy_gate after review passes)
result = app.invoke(
    {
        "requirement": "Build a JWT authentication system with refresh tokens, "
                       "rate limiting, and secure password hashing using bcrypt.",
        "messages": [],
        "iteration_count": 0
    },
    config
)

print("=== Execution paused at deploy gate ===")
print("Messages:", result["messages"])
print(f"Review passed: {result['review_passed']}")
print(f"Iterations: {result['iteration_count']}")
print("\n--- Human reviews the code and approves ---")

# Human approves deployment
app.update_state(config, {"human_approved": True})
final_result = app.invoke(None, config)

print("\n=== Final Result ===")
print(f"Deploy status: {final_result['deploy_status']}")
print(f"Total messages: {len(final_result['messages'])}")
for msg in final_result["messages"]:
    print(f"  {msg}")

from langsmith.schemas import Example, Run

def conciseness_evaluator(run: Run, example: Example) -> dict:
    """Custom evaluator: penalize answers that are too long."""
    prediction = run.outputs.get("answer", "")
    word_count = len(prediction.split())

    if word_count <= 30:
        score = 1.0
    elif word_count <= 60:
        score = 0.7
    else:
        score = 0.3

    return {
        "key": "conciseness",
        "score": score,
        "comment": f"Answer has {word_count} words"
    }

def contains_no_hallucination(run: Run, example: Example) -> dict:
    """Check that the answer doesn't contradict the reference."""
    prediction = run.outputs.get("answer", "")
    reference = example.outputs.get("answer", "")

    # Simple keyword overlap check (in production, use LLM-as-judge)
    ref_keywords = set(reference.lower().split())
    pred_keywords = set(prediction.lower().split())
    overlap = len(ref_keywords & pred_keywords) / max(len(ref_keywords), 1)

    return {
        "key": "no_hallucination",
        "score": 1.0 if overlap > 0.3 else 0.0,
        "comment": f"Keyword overlap: {overlap:.2f}"
    }

# Use custom evaluators in evaluation
results = evaluate(
    predict,
    data="qa-eval-set",
    evaluators=[conciseness_evaluator, contains_no_hallucination],
    experiment_prefix="support-bot-v2-custom-eval"
)

"""
Multi-Agent Content Creation Pipeline with LangGraph.
Requirements: pip install langgraph langchain-openai langsmith tavily-python
Env vars: OPENAI_API_KEY, TAVILY_API_KEY, LANGCHAIN_TRACING_V2=true,
          LANGCHAIN_API_KEY, LANGCHAIN_PROJECT=content-pipeline
"""
import operator
from typing import Annotated, TypedDict
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, SystemMessage
from langgraph.graph import StateGraph, END
from langgraph.checkpoint.memory import MemorySaver
from langsmith import traceable
from tavily import TavilyClient

# ─── State Definition ───────────────────────────────────────────────────────

class PipelineState(TypedDict):
    topic: str
    research: str
    draft: str
    feedback: str
    revision_count: Annotated[int, operator.add]
    final_article: str
    status: str

# ─── LLM Setup ──────────────────────────────────────────────────────────────

llm = ChatOpenAI(model="gpt-4o", temperature=0.7)
tavily = TavilyClient()

# ─── Agent Nodes ─────────────────────────────────────────────────────────────

@traceable(name="research_agent", run_type="chain")
def research_agent(state: PipelineState) -> dict:
    """Search for information on the topic and compile research notes."""
    topic = state["topic"]

    # Use Tavily to search the web
    search_results = tavily.search(
        query=topic,
        max_results=5,
        include_raw_content=False
    )

    # Compile research from search results
    sources = []
    for result in search_results.get("results", []):
        sources.append(f"- {result['title']}: {result['content'][:200]}")

    research_summary = llm.invoke([
        SystemMessage(content="You are a research analyst. Summarize the following search results into clear, factual research notes. Include key statistics and quotes."),
        HumanMessage(content=f"Topic: {topic}\n\nSearch Results:\n" + "\n".join(sources))
    ])

    return {"research": research_summary.content, "status": "researched"}


@traceable(name="writer_agent", run_type="chain")
def writer_agent(state: PipelineState) -> dict:
    """Write an article draft based on the research."""
    feedback_context = ""
    if state.get("feedback"):
        feedback_context = f"\n\nPREVIOUS FEEDBACK TO ADDRESS:\n{state['feedback']}\n\nPREVIOUS DRAFT:\n{state['draft']}"

    response = llm.invoke([
        SystemMessage(content="""You are an expert content writer. Write a compelling, well-structured article.
Rules:
- Use clear headers (##) for sections
- Include an engaging introduction and conclusion
- Cite research findings naturally in the text
- Keep paragraphs short (3-4 sentences max)
- Total length: 500-800 words"""),
        HumanMessage(content=f"Topic: {state['topic']}\n\nResearch Notes:\n{state['research']}{feedback_context}")
    ])

    return {"draft": response.content, "revision_count": 1, "status": "drafted"}


@traceable(name="editor_agent", run_type="chain")
def editor_agent(state: PipelineState) -> dict:
    """Review the draft and provide feedback or approve."""
    response = llm.invoke([
        SystemMessage(content="""You are a senior editor. Review this article draft and decide:
1. If quality is HIGH (clear, engaging, well-structured, factual) → respond ONLY with: APPROVED
2. If quality needs improvement → provide specific, actionable feedback (max 3 bullet points)

Be strict but fair. Articles must be publication-ready."""),
        HumanMessage(content=f"Topic: {state['topic']}\n\nDraft:\n{state['draft']}")
    ])

    content = response.content.strip()

    if "APPROVED" in content.upper() and len(content) < 50:
        return {"feedback": "", "status": "approved"}
    else:
        return {"feedback": content, "status": "needs_revision"}


@traceable(name="publisher_agent", run_type="chain")
def publisher_agent(state: PipelineState) -> dict:
    """Format the approved article for publication."""
    response = llm.invoke([
        SystemMessage(content="""You are a publishing formatter. Take this approved article and:
1. Add a compelling title (# Title)
2. Add a 1-sentence meta description
3. Add 3-5 relevant tags
4. Format with proper markdown
5. Add a "Key Takeaways" section at the end (3 bullets)

Output the final formatted article ready for publication."""),
        HumanMessage(content=state["draft"])
    ])

    return {"final_article": response.content, "status": "published"}

# ─── Routing Logic ───────────────────────────────────────────────────────────

def should_continue_editing(state: PipelineState) -> str:
    """Route based on editor decision — max 3 revisions."""
    if state["status"] == "approved":
        return "publish"
    elif state.get("revision_count", 0) >= 3:
        return "publish"  # Force publish after 3 revisions
    else:
        return "revise"

# ─── Graph Construction ──────────────────────────────────────────────────────

workflow = StateGraph(PipelineState)

# Add nodes
workflow.add_node("research", research_agent)
workflow.add_node("write", writer_agent)
workflow.add_node("edit", editor_agent)
workflow.add_node("publish", publisher_agent)

# Add edges
workflow.set_entry_point("research")
workflow.add_edge("research", "write")
workflow.add_edge("write", "edit")

# Conditional edge: editor can loop back to writer or proceed to publish
workflow.add_conditional_edges(
    "edit",
    should_continue_editing,
    {"revise": "write", "publish": "publish"}
)

workflow.add_edge("publish", END)

# Compile with checkpointing (enables human-in-the-loop)
memory = MemorySaver()
app = workflow.compile(
    checkpointer=memory,
    interrupt_before=["publish"]  # Human approval gate before publishing
)

# ─── Run the Pipeline ────────────────────────────────────────────────────────

def run_pipeline(topic: str) -> str:
    """Execute the full content pipeline with human approval."""
    config = {"configurable": {"thread_id": "content-001"}}

    # Start the pipeline — will pause before "publish"
    result = app.invoke(
        {"topic": topic, "revision_count": 0},
        config=config
    )

    print(f"\n{'='*60}")
    print(f"Pipeline paused for human approval.")
    print(f"Status: {result['status']}")
    print(f"Revisions: {result['revision_count']}")
    print(f"{'='*60}")
    print(f"\nDraft preview:\n{result['draft'][:500]}...")

    # Simulate human approval (in production, this waits for API call)
    approval = input("\n\nApprove for publication? (yes/no): ")

    if approval.lower() == "yes":
        # Resume the pipeline
        final = app.invoke(None, config=config)
        print(f"\n\n{'='*60}")
        print("PUBLISHED!")
        print(f"{'='*60}")
        print(final["final_article"])
        return final["final_article"]
    else:
        print("Publication cancelled.")
        return ""

if __name__ == "__main__":
    article = run_pipeline("The impact of AI agents on software development in 2025")
